The short version

Context Music Manager began as a weekend mod that played your own music instead of the game's. It now ships a purpose-built native audio engine, a calibrated acoustic model for sound travelling through a voxel world, and an in-game radio you can craft, place, tune and hear from the next room.

The through-line is a single adversary: the game's frame loop. Unity's audio system, the garbage collector and the main thread are all hostile to continuous music. Almost every major architectural decision in the project is another step away from them — and the payoff is not a feature you can screenshot. It's an absence. No stutter.

The second through-line is measurement. Twenty-eight purpose-built tools exist in this repository for no reason other than to find out whether something is true. Several major features exist only because a harness proved the previous version wrong, and at least three times the project discovered it had spent weeks tuning something nobody had actually heard.

The third, which only becomes visible in the last fortnight, is derivation over ownership. Again and again a bug turns out to be a piece of state that someone latched — a cached block id, an owner of a lane, a decision written down at the moment it was made — where the correct answer was to ask the world afresh every tick. It is now written into the project's own notes as a rule.

Act IJune 2 – June 17 · 18 commits

A weekend mod

The first two commits are "Add .gitattributes and .gitignore" and "Add project files" — a Visual Studio C# class library targeting a game's Harmony patching system. What follows is exactly what you'd expect from someone scratching an itch: caching on day two, crossfading on day two, and a toggle for each on day three.

By day four the real problem has surfaced, and it isn't playback:

Fixes in logic to address contexts changing too quickly — Jun 5
Fixed Vehicle Contexts — Jun 5

This is the problem the whole project is actually about, found on day four and never fully put down. A music system driven by game state is a debouncing problem before it is an audio problem. The game's notion of "you are in combat" flickers; a naive mapping from state to track produces music that changes every two seconds, which is worse than no music at all.

June 6 is the first big day, and the commit message reads like a week's work: POI detection, sleeper detection, POI tiers 1–5, infested and cleared states, blood-moon combat, low-health — and the contexts move from a list into a dictionary. Buried in the same message:

Hot Loading (removing/adding files while game running) went from an unintended glitch to intentional feature

Why — the glitch that became a contract

Promoting hot-reload from bug to feature looks like a throwaway line, and it isn't. It committed the project to a promise — you can reorganise your music while the game is running — that reached down into the architecture three weeks later.

If a track is playing from an open file handle, its folder is pinned. You cannot move it. Honouring the promise is why June 29 reads "Buffer audio files into native memory on open to avoid locking music folders": read the file into off-GC native memory, close the handle immediately, and the folder is free. Files over a size cap still stream, which is the honest compromise.

One casual user-facing promise, made in week one, forced a memory-management decision in week four. This pattern repeats throughout the project, and it is the clearest early sign that the author was designing for users rather than for a demo.

The NAudio detour

Three commits in a row are "Commiting before rewrite before implement NAudio", "Before adding NAudio. Didn't get around to it last time" and finally, on June 10, "NAudio System added — issues with resume and load time". Unity's own audio clip loading was too slow and too coarse; NAudio is the standard managed answer.

It will be removed entirely eighteen days later. Its NuGet packages are still sitting in packages/ today — NAudio, NAudio.Vorbis, NVorbis, CSCore, Concentus, BunLabs.NAudio.Flac — a small archaeological layer of every managed decoder that was tried before the answer turned out to be "none of them."

The act closes with two commits that are almost apologetic in their honesty:

Update before major changes. Spawn/Death PlayOnce don't work until they've been played once. Lag during title screen on load still. Ogg files still don't resume — Jun 14
After Several Upgrades — Flacs don't lock up, menu music still iffy — Jun 17

Every one of those three named defects — deferred one-shots, load-time stalls, seek-resume on compressed formats — gets a permanent architectural answer later. The Ogg resume bug in particular resurfaces in August as the root cause of a completely different symptom (silence in traders on Alpha 20) and is finally traced to Opus resume re-seeking mid-file into a premature end-of-stream.

Act IIJune 20 – June 29 · 40 commits

Becoming software

Ten days that turn a mod into an engineering project. The code is modularised into partial classes, the configuration moves into XML, the decision logic moves out of the DLL entirely, and the mod starts shipping as one binary for four different games.

One binary, four game versions — June 23, v1.0.1

7 Days to Die changed its API repeatedly across Alpha 20, Alpha 21, 2.6 and 3.x. The project's own audit lists ten distinct divergences, and the dangerous thing about them is that per-version compilation hides them:

DivergenceShapeWhy a compile can't see it
TraderInfo.IsOpenproperty on A20/A21/2.6, field on 3.0Both compile as x.IsOpen
Prefab.PrefabNamesame split, different boundaryIdentical at the call site
GetPOIAtPosition()1, 2 or 3 parametersC# bakes default arguments in at the caller
Rainfall...Percent() on 3.0, ...Value() on alphasPlain rename — missing method at JIT
EnumGamePrefsordinals drift: 170 → 175Enums bake in as integer constants
GetWorldPrefabsfills your list on 3.x, returns one on 2.6Found in August, not June

The EnumGamePrefs one is the nastiest in the list. A binary compiled against 3.0 that reads OptionsDynamicMusicEnabled on Alpha 20 does not throw — it silently reads a different setting. The fix is GamePrefsCompat, which resolves the enum member by name at runtime.

The project found these by decompiling all four games and diffing member shapes — not by reading source or counting #if blocks, neither of which can see a field/property split. By August this had been automated into a tool.

Why — the support burden, not the elegance

Shipping four downloads is easy. What's expensive is everything after: four sets of release notes, four chances to grab the wrong file, and a bug queue where the first question is always "which version did you install?" One file that loads everywhere converts a permanent support tax into a one-time engineering cost.

The tell that this was the reasoning is July 2: "Runtime-generate the cmm console command (removes the last per-version fork)." Nobody removes the last fork for performance. You do it because a single remaining fork means you still have four build outputs, and the whole point was to have one.

The same instinct produced one of the more elegant hacks in the repository. Two generations of the game's mod loader disagree about the shape of ModInfo.xml: Alpha 20 wants a nested <ModInfo> element, everything since wants flat fields. The shipped file satisfies both at once, because A20's loader matches on the element's qualified name while the newer loader routes on a namespace-sensitive XLinq query. Putting the legacy block in a default namespace makes it invisible to the new loader and perfectly visible to the old one.

The music logic leaves the DLL — June 26

In a single day: BuildSnapshot() is extracted from ResolveContext(), a MoonSharp interpreter is embedded, the resolver is ported to Lua, cut over, and the C# version is deleted.

Extract BuildSnapshot() from ResolveContext()
Add ScriptHost: MoonSharp-hosted Lua decision layer
Rename GameSnapshot/snap to GameState/gameState
Cut context resolution over to context.lua
Drop the built-in C# resolver; embed context.lua as the baseline

The entire policy — priorities, the weighted combat-threat model, day/night rules, biome rules, fallback chains — now lives in Config/context.lua, 300 lines. It hot-reloads on save. It runs sandboxed with no file or OS access. A pristine copy is embedded in the assembly and used automatically if the on-disk file is missing or fails to compile, so a broken edit cannot take the audio down. Delete the file and the default returns.

Why — this is the part that is a matter of taste

Everything else in the mod has a right answer. Does the FLAC decode? Does the crossfade click? Those are correct or they aren't.

When should combat music start has no right answer. It depends on how you play, your difficulty, and your temperament. Any value the author picks will be wrong for a large fraction of users — and each of those users would otherwise be a bug report that can only be closed by shipping a new build.

Moving the policy into a hot-reloading script converts the most contentious surface in the project from "file an issue and wait for a release" into "edit a file, alt-tab back." The embedded-fallback detail is what makes it safe to hand players a live wire: the worst outcome of a bad edit is that the default comes back.

Note also the deletion of the C# resolver. Keeping it as a fallback would have created two implementations of one policy that could disagree — a failure mode the project runs into for real, at enormous cost, two months later in the acoustics work.

Loudness normalization — June 26, v1.0.3

EBU R128 measures every track once and caches the result by content hash, so tracks from different albums play at a consistent perceived level.

Why — it's load-bearing for the core promise

The mod's pitch is "play your own library." A personal library spans decades of mastering practice — a 1994 CD rip next to a 2019 loudness-war master is a 12 dB jump. Without normalization, the headline feature actively produces a worse experience than the game's own curated soundtrack. R128 isn't a nicety here; it's what makes "your music" viable at all.

Biome combat music, and the two-clocks insight — June 26, v1.0.2a/b

Fight in the wasteland, get wasteland combat music. Two details show unusual care. The biome locks when the fight starts and holds for the whole continuous fight, so running across a border mid-battle doesn't swap the track. But if you break off and re-engage somewhere new, it re-locks to the new biome while keeping the intensity tier you'd escalated to. Leave a fight in the wasteland at Boss intensity, re-enter in the desert: you get the desert track, still at Boss.

Why — two clocks, running at different rates

Naively, "which music" is one question. It's two. Where you are changes at walking speed; how bad it is changes over the arc of a fight and shouldn't reset because you stepped across a line on a map. Treating them as one variable produces either music that flickers with your footsteps or music that ignores where you are.

The same insight produces warmgroup the same week — day and night versions of a context share a warm-up timer, so switching between Home and Home_Night doesn't restart the dwell and leave a gap where the wrong track cuts in.

Act IIIJune 28 – July 3 · 57 commits

The engine goes native

The largest technical arc in the project, and the one with the clearest payoff.

The problem. Music played through Unity competes with the game for the main thread and is frozen by garbage collection. A GC pause is stop-the-world for all managed threads, so there is no managed opt-out — you cannot fix this with better C#. On a horde night, when GC pressure and chunk streaming peak simultaneously, the ring buffer underruns and you hear it.

The answer was to leave, in stages. Each stage removes one more thing that can be suspended:

StageDateWhat moved out of managed code
1Jun 28Decoding → CMM_Decoder.dll. NAudio removed entirely.
2Jun 29Buffering → off-GC native memory; file handles close immediately.
3Jun 30Output → miniaudio on the mod's own thread. The Unity AudioSource path is deleted the same day.
4Jul 1The mixer → the per-sample producer loop, rewritten in C.
5Jul 1Loudness → R128 analysis follows it native.
6Jul–AugHousekeeping → advance, config reload, file watching move onto CmmScheduler, off Unity's frame loop.

The split the project settled on is the load-bearing design decision of the whole codebase:

C# stays the brain

Which file, when. Fades, resume, loudness bookkeeping, auto-advance, cooldowns, context policy. Infrequent, and GC-tolerant.

C becomes the hands

Decode → convert → gain → sum → write. Never touches the managed heap. Never suspended.

Why — the boundary is drawn at frequency, not at subject

The obvious way to split a codebase is by topic — "all audio in C, all game logic in C#." That is not what happened. Decoders are still opened in C#, off-thread, once per track; the handle and format kind are then handed to cmm_mix_add and the mixer reads natively from there.

The line is drawn at how often the code runs. Anything on the per-sample path is native. Anything that happens once per track can stay managed, because a GC pause during a decision is invisible — you have hundreds of milliseconds of buffered audio to absorb it. A GC pause during the mix loop is a click.

That's a more disciplined boundary than "rewrite it in C," and it's why the C# side is still ~37,000 lines in the mod proper. The rewrite was surgical.

What it buys, concretely

  • Music survives loading freezes. Because the engine owns its threads, tracks keep playing — and keep advancing to the next track — while the game's main thread is stalled loading a world.
  • Crossfades stop being clobbered. The old system had exactly two channels. If a new context fired mid-crossfade it had to steal one and hard-cut. The native mixer holds four music voices (with array headroom to 20 for emitter and effect voices), so ambient → tension → combat in two seconds is one continuous handoff.
  • Eviction is inaudible. Past four voices, the mixer drops the most-faded one — already nearly silent at the tail of its fade. The incoming track is never sacrificed.
Why four voices, and why the quietest one

Four isn't an audio-engineering number. It's a game number: it's how many context changes 7 Days to Die can throw at you before the first fade finishes. The mixer is sized to the game's rate of change, not to a mixing convention.

The eviction rule is the sharper decision. When you must drop something, the question is which loss the player will notice. The tail of an old fade is near-silent — nobody hears it go. The incoming track is the one the player is waiting for; cutting it is the loudest possible failure. "Sacrifice the quietest, never the newest" reads as obvious once stated, which is usually the sign of a rule someone learned the hard way.

Defect of the act

Race-free native file reads: normalize FLACs of any size

Concurrent native file-opens were crossing each other's C-runtime FILE* buffers, so drflac_open returned NULL. FLAC tracks were then silently left un-normalized, playing too loud or too quiet with no error logged anywhere. The fix was to decode off raw Win32 handles rather than the CRT. A size cap that had been papering over it was removed at the same time, so all sizes normalize.

Act IVJuly 4 – July 18 · 21 commits

Music in the world

Until now the music was in your ears. Now it comes out of objects.

World emitters (July 4). Radios, jukeboxes and speaker blocks play music where they physically stand, through a native spatializer and reverb. A POI you're clearing has music coming from a corner of it.

Doors (July 8). Sound routes through doorways and around corners rather than through walls. Opening, closing or damaging a door changes what gets through.

The personal radio (July 10). Alt+PgUp / Alt+PgDn step through stations. Stations are subfolders of the Radio source — the folder name is the station name. Everyone on a server hears the same song at the same moment, and a station keeps broadcasting while you're away, so tuning back in drops you into whatever is playing now, mid-track.

Why "a station is a folder" is the best small decision in the project

There is no station manifest, no registration XML, no UI to define one. Make a folder, name it, put music in it.

Compare the alternative: a stations.xml listing name, path and ordering. It would work, and it would be worse in every way that matters. It's a second source of truth that can disagree with the disk. It breaks when someone renames a folder. It needs its own migration when the schema changes. It needs documentation, and eventually a UI.

Choosing the filesystem as the data model means the feature has no configuration surface at all — and therefore no configuration bugs. The same instinct shows up again in August, when add-on music packs turn out to need no registration file either: the convention is simply <mod>/Music.

The sync problem, and its answer

The world emitters and the personal radio drifted audibly apart. The measured cause is lovely: the game's worldTime advances at roughly 0.89× realtime, while audio decoders run at exactly 1.0×. Every voice outran the worldTime-based schedule by about 7 seconds per minute, and different consumers re-synchronised at different moments.

The fix was to stop trusting game time. The broadcast clock (CmmClock) is anchored to worldTime at world entry, then runs at realtime rate, freezes during single-player pause, and carries worldTime jumps. A second round handled 3.0 saving the world synchronously on the pause edge — a ~2.5 second stall — by attributing clock intervals to their starting pause state and accumulating resync debt for sub-second pauses.

Why this is harder than it looks

"Everyone hears the same song" sounds like a networking problem and is actually a clock problem. There is no message you can send that fixes a schedule computed from a clock running at the wrong rate; you'd just be re-syncing to the same drift every time. Finding that worldTime runs at 0.89× requires instrumenting and measuring, not reasoning — and the project built [CMM SYNC] audit logging specifically to do it.

July 18 closes the act with the least glamorous and most important fix in it: installing the mod on a dedicated server had been freezing joining players at the loading screen. The answer was a general one — a dedicated-server inert gate, a CmmGuard convention that wraps every Harmony patch body so a throw inside one can never take the game down, and producer-owned device lifecycle so a headless process never opens an audio device at all.

Act VAugust 13 – August 23 · ~250 commits

The acoustics rebuild

The most unusual stretch of the project. Roughly 250 commits in eleven days, almost all on one question: what does sound do inside a voxel world?

There is a three-week gap in the log before it — July 18 to August 8 — and the work resumes with a retarget to game build 3.1.0 b14 and the discovery that the game's Overall volume slider had never reached the mod at all, because CMM's audio leaves through its own output device rather than Unity's. Turning the master to zero silenced the entire game except this mod.

Then the acoustics. The existing occlusion model worked, but nobody could say whether it was right — it was uncalibrated. So it was rebuilt from a written specification, with reference scenarios, an automated acceptance gate, and offline audio rendering so changes could be listened to rather than argued about. The commit log reads like a research notebook:

synth + scenarios: controlled geometry finds three defects in the NEW model
ref: the unifying principle — transmitted and diffracted sound RADIATES
ref: write the model down — the document whose absence cost a day
The gate was wrong: passivity replaces reach, and the calibration was in the wrong place
The renderer was evaluating a DIFFERENT MODEL than the gates, and summing coherent copies
Four routed-leg formulations measured; the orphan gate may itself be wrong

The model that emerged is genuinely sophisticated: portal graphs seeded from air pockets around a speaker, Dijkstra routing between rooms, Fresnel-disc transmission treated as an area integral, a diffuse field coupled through apertures, per-arrival delay producing cave echoes, and bottom-up region segmentation that discovers rooms and corridors with no grid. It was then ported to native C in five stages, each verified against the reference, finishing at 0.02 dB agreement.

And then it was replaced.

August 20 — one field, centred on the listener

The trigger was blunt. The user A/B'd the models in-game and reported the new one "completely broken on native, works on legacy" — and added a requirement that killed the whole per-speaker approach: it must handle moving sources, because zombies get sound later.

There is ONE pair of ears and there may be fifty noise-makers, some walking. So compute nothing per source: flood ONE field from the listener a few times a second; a source looks up where it stands. Attenuation is symmetric, so a listener-anchored field answers for a source exactly.

Measured: 0.11 µs per source lookup. Two tuning knobs total.

Why this is the best decision in the project, and why it hurt

The topological model was more correct. It reached exact parity in native C. It modelled diffraction and reverb coupling properly. And it lost.

It lost because a live game is not a scenario file. Sources move. Chunks stream in and out. Doors swing while you're reading the geometry. Every one of those is a cache invalidation problem for a per-speaker model, and the preceding week's bug list is almost entirely cache staleness — including one measured case where native handed back stale geometry for 33 seconds straight.

The listener-anchored field doesn't solve those bugs. It makes them impossible: nothing persists long enough to go stale. A door is just in the next flood. No patching, no settling gate, no handover, no second model. That distinction — cannot occur versus is fixed — is the most valuable sentence in the repository. And the decision cost a month of correct work, which is exactly why most projects don't make it.

There's a second, quieter win in there. The field carries excess attenuation only — what the building adds over a clear line — and leaves distance to the mixer. So clear line of sight is 0 dB by construction, not by tuning. That's a whole category of "why does it sound muffled standing right next to the speaker" bugs designed out rather than debugged.

Doors became apertures — August 22

A door's leaf cannot be read while it moves: the game blanks its colliders for the entire swing. Measured — a door at 29.5% through its animation reports no collider at all while its leaf still fully spans the cell.

So the door stopped being a leaf and became an aperture: the plane is measured once while readable and remembered, and the openness ramp supplies how much of it is blocked. Fixed geometry, moving number.

The prior attempt — synthesising a leaf position from the door's rotation — was worse than nothing. Its guessed slab at 0.5 against a body at 0.480 put the door on the wrong side of the listener: one frame after the latch, player standing still, a far-side speaker jumped from 14.9 dB occluded to 0.0 dB.

A door with no remembered plane now gets NO plane — the isotropic lump is blunt but symmetric, and a guessed plane is confidently wrong in the one direction you are listening.

The project notes, correctly, that fixed-geometry-moving-number is what Wwise, FMOD and Project Acoustics all do. It arrived there independently, by measurement.

The defects, which are excellent on their own

Furniture is not air: a model entity's collision flags and bounds both lie
An unloaded chunk is not open sky: the scene was rebuilding into a different world
A week on the wrong speaker: the nearest-point diagnostic reported the LAST station
The listener was half a block off: 4 dB of occlusion standing next to a speaker
A floor is not decorative trim: 90% of every partial floor plate was being discounted
woodShapes:cube was charged HALF a wall: ask the variant, not the shape class
A metal door is not a metal wall: cap what a shut door is made of
My earlier "open air" tests floated 4 blocks up — the version of open air nobody stands in

That last one is the most instructive failure in the project: the test was passing because the test was wrong, in a way that only a human standing on the ground in-game would ever notice.

Act VIAugust 20 – August 23 · interleaved

The library, and the things that take longest

Every track plays before any track repeats

The old RandomNoRepeat remembered exactly one track. Over a 200-track folder that lets a track return on the very next pick, and the birthday effect makes an early repeat likely within a session. Measured over 400 runs: the old behaviour repeated something after an average of 18 tracks, and as soon as 3. A large soundtrack didn't feel large.

The replacement is a per-context shuffled bag. Three details are worth the detail:

  • It commits at PLAY, not at pick. Three of the six callers that pick a track are speculative — the staged pin, the pre-staged advance, the missing-file replacement walk — and their picks are routinely discarded. A bag consumed at pick time would drain without a note being heard.
  • FavouriteWeight now scales with folder size. As a raw multiplier it meant "every 45 minutes" at 40 tracks and "every 19 hours" at 1000. Now measured constant at 5.7% of airtime from 50 tracks to 5000.
  • Selection allocates nothing. It walks the pool twice rather than building a candidate array, which past ~10,600 tracks was a large-object-heap allocation on every pick.
Why the FavouriteWeight fix is the most user-respecting change in the release

A setting must mean the same thing regardless of library size. If "favourite" means noticeably-more-often at 40 tracks and never at 1000, then the setting is lying to the larger half of the userbase — and worse, it's lying silently, in a way no user could diagnose. Scaling it against a 50-track reference makes the promise size-independent.

Config files stopped being shipped

Updating the mod had been overwriting every setting the player had chosen. Now the files are generated on first run and migrated by schema — today 202 settings across two files, one table describing all of them, with since: for additions and changedIn:/was: for changed defaults. A changed default is applied only to users still sitting on the old one; comparison is on the parsed value, so 0.50 and 0.5 count as the same untouched setting.

Music packs became ordinary mods

Requested by a soundtrack author, who called it "the single feature I'd request." Previously a soundtrack had to be copied into CMM's own music folder, which made CMM and the soundtrack one blob on disk — exactly what a mod manager cannot cope with. Now every installed mod's Music folder feeds the rotation. Under MO2 or Wabbajack, CMM and a soundtrack stay separate mods with independent pages, versions and provenance.

Notably, the planned design had mods declare a music root via a small XML. The shipped version has no registration file at all.

The radio dial, and knowing when to stop

The radio click was a pop, not a switch: rebuild it out of damped modes
Clicks were tonal because I was hitting the resonators with an impulse
Put the contact back: a deterministic strike on top of the noise
Chatter and saturation for grit — and four measurement bugs found on the way
Fit the clicks to two reference recordings, and lift the clamp that made it impossible
Recorded clicks: a Sounds folder, and a different rate every firing

Synthesis got close and then stopped converging, so the final answer is recorded samples — held in RAM, varied ±2000 Hz per firing so no two are identical, and sitting in a Sounds/ folder players can replace with their own. The synthesised click remains as a fallback if a file is missing: a sound file can quieten the radio, never break it.

Tuning between stations

The station was fading up out of the noise, which is the one thing a radio never does
The arriving station is MANGLED, not faded
Between stations is a ROAR, not a hiss: drop the low cut that was killing its body
A receiver's noise floor is FIXED: stop scaling the static by the track's loudness gain

Getting there required building CmmRadioSim (renders a station change offline through the shipping DLL in four seconds) and CmmRadioLab (a UI that renders game against reference and A/Bs them). Settled numbers: leave 700 ms, static floor 100 ms, arrive 1000 ms, knee 0.90, noise 0.15. Press to tuned ≈ 1.8 s, with break-up starting 75 ms after the key.

Why build a whole offline simulator for a sound effect

Because in-game listening had already cost weeks — twice — and the project worked out why.

The first cause: Config/radio.xml held hand-edited values that no migration could ever reach, because migration only rewrites a key still holding a recognised former default. Every in-game listening round for weeks was spent judging a sound nobody had approved.

The second: "A demo is not a keypress." The tuning had been settled on rendered demos, where nobody presses a button and waits — so the two-thirds of a second of dead air after the keypress was invisible in every test that approved it.

v1.0.5-rc1 is tagged on August 23. On the same day, the project writes its own development history to that point — docs/HISTORY.md, 40 KB. This document is its successor.

Act VIIAugust 24 – August 30 · 220 commits

The last week

The single densest stretch in the project: five release candidates in seven days, 76 commits on August 29 alone. Nominally this is "polish before 1.0.5 final." In practice three genuinely new subsystems land, and the project discovers a bug shape it had been fighting since June without naming.

Doors, finished — Aug 24–26

The August 22 aperture rebuild made doors correct. This week made them good, and the log is a compressed course in how to measure a moving object you are not allowed to look at:

A door is a leaf, not a solid block the size of its multiblock
The latch flips before the leaf moves, and a constant radius cannot cover a big door
A double door has two leaves; the model only ever remembered one
A tilted plate is not its bounding box
A cell the leaf has swung out of is air, and it was charging 26.8 dB
A threshold in metres, divided by a seven-metre span, is a door that is open at 10%
Doors: ask how many square metres are open, not how far through the swing
On most door rigs the collider lies; believe the renderer
Read the leaf's real travel, not the clip's clock
Lead the door by the pipeline's own latency
A closing door can only get more shut
One time constant, in seconds, the same for every door and every listening position

Three of those are worth unpacking, because each replaces a proxy with a measurement.

Open area, not swing fraction. A door's gap had been measured along its largest dimension — which for an ordinary door is its height, so it read acoustically fully open at 40% of its swing, and a seven-metre drawbridge read open at 10%. The threshold moved from metres of gap to fraction of the aperture's area, and every override in the config was converted with it.

Believe the renderer. On most door rigs the collider lies during animation, so the leaf's real travel is read from the renderer transform rather than the animation clip's clock. A door that bounces at the end of its swing is not "at the open pose"; a leaf that slides rather than turning is not rotating at all.

Lead by the pipeline's own latency. Because the field publishes at 4 Hz and the audio slews behind that, a door's acoustic change arrives late. So the model leads the door by the measured latency of its own pipeline — and a set of commits exists purely to find out what that latency is:

The door stopwatch was timing floods that had never seen the door
A stopwatch that runs all the way to the ear
Having computed the answer, do not sit on it for a tick

Why the stopwatch commits matter more than the fixes

Four wrong diagnoses in one session, all of them arithmetic over an untimed chain. The pattern the project names afterwards is measure, don't estimate: when a stage's cost is unknown, a plausible number gets substituted for it, and the resulting total is confidently wrong. The answer was to put a stopwatch on every stage and, where a stage was still opaque, to split it in half and time the halves.

Note also the ordering of the last two: speeding the tick up made things worse, because the rate limiter downstream throttled harder. That's a system where the obvious knob has the opposite sign — the exact case where estimating fails and only instrumentation survives.

The coverage panel — Aug 26

A new HUD on Alt+Numpad8, cycling off → everything → gaps only. One row per context: whether it has music of its own, how many tracks, and — when it has none — the fallback chain it walks, with the context that will actually be heard marked at the end of it. Radio stations are listed individually, since a station with no tracks is dead air rather than something a fallback covers.

The panel reads disk, not the engine's cached snapshot — because a diagnostic that reports the engine's opinion cannot tell you the engine's opinion is wrong.

Why this is a release blocker disguised as a HUD

The mod's central failure mode is silence, and silence has many causes that all look identical from the player's chair: no files, wrong folder, a context that never resolves, a fallback chain ending nowhere, a station folder that's empty. Every one of those is a support ticket that costs an exchange of logs.

The coverage panel converts all of them into one glance. It is the first tool in the project aimed at the user's debugging rather than the author's, and it arrives immediately after the release-candidate line opens — which is the moment a project stops asking "does it work for me" and starts asking "can a stranger tell me what went wrong."

World speakers on 2.6, and the end of hand-surveying — Aug 29

Every speaker on game version 2.6 had been silent since the feature shipped. The cause is one of the best-shaped bugs in the repository:

The capability check required a composite tile-entity door — a type that only exists from 3.0 — as a belt-and-braces test, which is a check for DOORS standing in for a whole subsystem.

Doors became a capability (HasCompositeDoors) rather than a requirement, and 2.6 immediately gained stations, tuning, the acoustic field, reverb, the tuner menu and the craftable blocks. What it does not get is doors modulating occlusion mid-swing, because 2.6 models doors as block metadata with no tile entity and no animator — there is no swing to read.

Behind it sat a second divergence of the shape Act II catalogued: 3.x has void GetWorldPrefabs(List) which fills your list; 2.6 has List GetDynamicPrefabs() which returns the live one. A member-shape split that no per-version compile can see.

Three of these got through hand-surveys of decompiled source in a row, each through the gap the previous method left — name exists, then declaring type, then signature, then a type nobody thought to check. So the project stopped hand-surveying:

Stop hand-surveying the game API; ask the DLL what it calls — Aug 29

tools/CmmApiDiff reads the shipped assembly's own member references out of its metadata — no assembly is loaded or executed — and diffs them against what each game version actually declares. The question stops being "did I remember to look here" and becomes "what does it call", which is not a matter of opinion.

Tuning a speaker by looking at it — Aug 29

Deterministic, identical for every player on a server, and free of persistence — all deliberate — but the answer to "I don't want this station in this house" was to go and rename folders on disk.

Craftable speakers, built in code — Aug 29

A shelf speaker and a ham radio, craftable in the backpack. It started as a Config/recipes.xml patch and moved into C# for two reasons, the second fatal:

  • An XPath patch cannot ask whether the session is single player. It is applied at config load, long before there is a session — so an XML version had to add the recipes always and take them away afterwards.
  • Alpha 20 has no ham radio block at all. And RecipesFromXml does not skip a recipe whose output it cannot resolve — it throws, taking recipe loading down with it. One payload ships to all four versions, so an XML recipe naming a block A20 lacks would have bricked crafting on A20 for anyone who installed the build.

Built in code, a missing block is simply a recipe quietly not offered. And single player is checked as a state on a timer, not a launch option, because a host who started alone can have someone join at any moment — at which point the recipes are withdrawn, because the blocks they make are only heard by the machine that placed them.

The carrier, and 76 commits in one day

August 29 is the largest day in the project's history, and almost all of it is one subsystem: what a world speaker does while it is changing station, and what it does when the station it is tuned to has nothing to play.

The second of those is the carrier — a real radio tuned to a dead frequency does not go silent, it sits on a tone. CMM's carrier is a minor triad (440 / 523.25 / 659.25 Hz) whose root is displaced by up to WorldEmitterOffAirVarianceHz, seeded from the station's name. So a dead channel keeps the same pitch on every client and across restarts: something you can learn, rather than a pitch that moves under you. The upper partials are quieter than the root, because a carrier is a tone with harmonics and not a chord.

The retune is the harder half, and reading the day's log in order is the clearest picture of how this project debugs anything:

Six ABI revisions in one day (56 → 59, then 60–62 the next). The architectural resolution is "one decode, two lanes": a speaker changing station borrows a second render lane so the outgoing and incoming sound are the same decode crossing over, rather than a fade-out with nothing underneath it. Three of the six emitter slots are reserved for tuning so a retune can never starve a station that is playing.

The bug that names the week

The ghost: a station's advance decision was overwritten every tick

A function called MaintainOnAir re-derived whether a station was on air, every tick, over a decision that had just been made — so a track that had been told to advance looped its own tail instead. The same shape appears four more times in the same week: a carrier with an owner, a receiver with three owners, a lane index stranded on a dead station, a cached block-id table that outlived the world it was resolved against.

The project's own conclusion, written down on August 30: derive, do not latch. Nine reports from one shape — an owner plus event triggers, where the answer should have been derived from the world each tick. The carrier's final commit is literally "The carrier stops being a machine with an owner and becomes derived state."

Why this shape kept recurring, and what it costs

Ownership is the natural way to model a scarce resource: something holds the lane, something owns the carrier, something remembers which blocks are speakers. It is also the natural way to model it wrong in a system where the world changes underneath you — a station's folder is deleted, a radio is broken with a pickaxe, a world unloads and block ids are reassigned.

Every one of those makes an owner stale, and a stale owner in an audio system is silent by construction: the code path that would have made noise returns early. That is why these took a week and the acoustics took a day per bug — a wrong number is audible, a missing owner is not.

The listener-anchored acoustic field is the same lesson learned nine days earlier in a different subsystem. It is striking that the project had to learn it twice, and mildly encouraging that the second time it wrote the rule down.

Robustness, and a library that moves underneath you

Woven through the same week is a set of fixes that all share one premise: the music library is on a drive that may not be there. The author's own library lives on an exFAT external disk, which is why several of these exist at all.

The last of those is the most characteristic thing in the release. A file that is present and readable but that nothing can decode was recorded as unplayable and skipped — correct behaviour, and completely silent. Every instrument agreed with the silence: the file is on disk, so the coverage panel counted it; the playlist entry resolved, so the missing-entry report said nothing; the station had other tracks, so the "no playable tracks" warning never fired.

It was found by probing a real 3,381-track library through the shipping decoder. Twenty-five files were Apple Lossless inside an .m4a container, which is not a supported format. Each such file now gets one warning naming it, capped at twelve before it summarises — and a drive that has merely gone away still says nothing, because that distinction already existed and this was built on top of it.

The resolve tick

Ten times a second, on a Unity coroutine, three things happen in order.

1. Detection builds a snapshot. BuildSnapshot() reads the world into a flat GameState: biome, time of day, weather, health, vehicle, swimming, POI identity and tier and infestation, trader identity, nearby players, and the set of enemies currently targeting you with their class names and states. The marshal into Lua is change-gated — each scalar is cached and only the ones that moved are re-sent — which took the steady roaming tick from about twenty allocations to about one.

2. Policy decides which contexts are active. resolve(gameState, cfg) in context.lua returns a list of context tokens. The combat model is a weighted threat score: a standard walker is 1.0, a crawler 0.6, a dire wolf 4.5, a demolisher 8.0, matched by longest-substring against the entity class name so modded enemies fall through to a default weight. State multipliers stack on top (feral ×1.5, radiated ×2.0, charged ×2.75, infernal ×3.25). The total picks the highest tier whose threshold it reaches — Combat_Low at 0.5, Combat_High at 6, Combat_Boss at 18 — and the biome suffix is appended from the biome that was locked when the fight started.

3. The stack decides what plays. Active tokens are matched against contexts.xml, which carries priority, fallback mode, warm-up dwell, staleness, cooldown, fade-in time and per-context volume for 71 contexts. The highest-priority context that is playable wins; a context with no music of its own walks its fallback chain until it finds one that does.

Two numbers in tension

1.5 seconds of hysteresis against a 2.0 second crossfade

A context must be absent for 1.5 s before it is dropped from the stack — that's the debounce that answers day four's "contexts changing too quickly". CrossFadeDuration defaults to 2.0 s. So even the best case — a context appears, vanishes, and is evicted as fast as the rules allow — puts the out-transition inside the previous fade.

Measured in a 12-hour simulated session: 39.1% of all context transitions interrupt an in-flight crossfade (1,525 of 3,882), stable over 48 hours. Worst burst: three transitions in one 2.0 s window, with the mixer pinned at its four-voice cap.

The partial answer shipped is a per-context rule rather than a global one: a context driven by something that can vanish in seconds (enemies, nearby players, POI state) gets a fade that fits inside the hysteresis — 1.2 s with margin. A context driven by where you are or what time it is cannot flicker, and keeps its 5 s fade. The structural question — raise the hysteresis or refuse a transition mid-fade — is still open in the TODO.

The audio path

Everything below the decision is native. CMM_Decoder.dll is about 16,400 lines of C across five translation units, at ABI revision 62.

Every supported format is decoded by a vendored library behind one uniform five-function shape (open_file / open_memory / read_float / seek / close):

The container reader is worth a note of its own. It was originally eager — it read the whole file before playing — which stalls the game for a multi-gigabyte video. It was rewritten to stream: a lazy pull-remux with per-codec callback opens and AAC refill, where a seek rebuilds from zero. That is how a podcast in an .mkv plays without a hitch.

Buffering

Files under a size cap are read entirely into off-GC native memory on open and the handle is closed immediately, so the folder is never pinned and you can reorganise your library while it plays. Larger files stream. This is the direct descendant of week one's hot-reload promise.

Mixing and output

cmm_mix.c holds the producer loop: four simultaneous music voices with array headroom to twenty for emitter lanes and effects, per-voice gain and fade state, and eviction of the most-faded voice when the cap is reached. cmm_out.c is miniaudio on the mod's own thread. Neither touches the managed heap, so neither can be stopped by a GC pause.

Because the audio leaves through its own device rather than Unity's AudioListener, the game's volume sliders do not apply automatically — so CMM applies them by hand. Context music takes Overall × Music; world emitters take Overall × Ambient × WorldEmitterVolume, because a radio playing out of a block is an environmental sound and turning the music down should not silence the POI. The masters are slewed rather than stepped, so dragging a slider no longer clicks. Overall 70% with Music 20% lands at 14%, matching vanilla to well under a tenth of a decibel.

Loudness

EBU R128 integrated loudness, measured natively, keyed by content hash in Cache/loudness.xml. The store holds only what the user has actually touched — adjusted, banned or favourited — while live measurements last the session; an earlier version gained an entry for every track ever played and grew far past its intent. A long track is measured a second in rather than nine, so a podcast does not play at a guess for its opening. Death and spawn stingers bypass the gate entirely, because a measurement can never arrive for audio that short and waiting for one delayed them by up to three seconds.

The acoustic field

One field, flooded outward from the listener, read by every source. This is the piece the project threw a month of more-correct work away to get.

Three properties are load-bearing and each replaced a whole class of bug:

  • It carries excess attenuation only — what the building adds over a clear line. Distance stays with the mixer, so line of sight is 0 dB by construction.
  • It is rebuilt whole, never patched. A door that opens is simply in the next flood. There is no settling gate, no handover, no second model.
  • Cells carry six half-faces, not three faces. A cell's material used to live on its three negative faces, which meant the face between C and C+X belonged to C+X — so a route entering through one positive face and leaving through another paid nothing at all. A plane wall survived it, which is why every wall test passed; anything you can get around did not. A speaker walled in on four sides with open corners measured 0.1 dB where it should have measured 58.6.

The cell-size history is the clearest example of the project's measurement habit. Cells were 3×1×3, then 2×1×2, then 1×1×1, and each step was forced by the same failure on a different axis: a cell taller or wider than the thing it must represent cannot represent it. The bathroom test, reported by the user as "I'm in a bathroom, and closing and opening the door does nothing":

Doors

A door is an aperture: a plane measured once while the colliders are readable and remembered, plus an openness ramp derived from the leaf's real travel read off the renderer. The threshold is a fraction of the aperture's open area, so a garage door and a closet door behave consistently. Only hinged doors are treated as swinging. The model leads the door by the measured latency of its own pipeline, and a closing door can only ever get more shut.

On 2.6 none of this exists — doors are block metadata with no tile entity and no animator — so the swing machinery is disabled rather than fed constants. A door that changes instantly is honest there; one that pretends to swing is not. That work is scoped but not built.

The emitter layer

EmitterAudioLayer.cs is the largest file in the project at 4,212 lines, and it is essentially a small broadcast plant.

Detection. EmitterRegistry resolves speaker block names to block ids — per world load, never per process, because block ids are assigned per world and caching them across a world change is why "a speaker is never detected, and placing more doesn't help" was a real bug that only a full game restart cleared. Prefabs are enumerated through EmitterCompat, which binds the diverging 2.6/3.x method by name.

Grouping. Every speaker belongs to a group keyed by its POI. A large POI made of several RWG tiles is one building for station purposes, because thirteen radios inheriting a tile id made a house disagree with itself.

Station assignment. Pin, then cache, then hash. A player's explicit choice (Cache/emitters.xml, sectioned by save, keyed per radio) wins; otherwise the POI's prefab instance id hashes into the sorted station list, which is deterministic and identical on every client. Assignment is pinned by station name, so removing a folder means dead air rather than a silent retune. A radio you place yourself starts off.

Rendering. Six native slots, three reserved for tuning. Every speaker on the same station is one source at the right places rather than many decodes. A station's audio is mono-downmixed per slot, coloured, spatialised through the native spatializer, and given reverb graded by how much energy survives the bounces.

Voicing. WorldEmitterColorVoice (0.5) band-limits hard at both ends and adds the boxy resonance a cheap cone has; ColorDrive adds the crunch of one pushed too hard; ColorStatic a bed of hiss. Ham radios carry their own harder set at 0.9, because a communications speaker is smaller and nastier than a shelf unit. Every speaker has its own receiver, so the static comes out of the radio rather than out of the bus.

The carrier. A station that cannot play sits on a minor triad seeded from its name, at WorldEmitterOffAirLevel 0.04. It is derived state with no owner: every tick, the set of speakers listening to an unplayable station is worked out afresh, and the tone exists if that set is non-empty.

The radio

Stations are folders. Subfolders of the Radio source, merged across every installed music pack that supplies the same folder name.

The schedule is anchored, gapless and computed, not stored. Each station is a fixed name-seeded permutation with an anchor time; where a station is right now is arithmetic over the shared world clock, so it is instantly Ready at any pool size with no length scanning, identical on every client, and tuning in joins a broadcast already in progress mid-track. A background chain walk fills in the detail behind it. Deliberately, the anti-repeat bag that governs context music never touches stations — a fixed permutation already has the guarantee, and bans and favourites do not reach the radio.

The clock (CmmClock) is anchored to worldTime at world entry and then runs at realtime rate, freezing on single-player pause and carrying worldTime jumps, because the game's own clock runs at 0.89× realtime.

The dial. Alt+PgUp / Alt+PgDn walk Off → station → … → Off, wrapping both ways, so two keys give on, off, next and previous. Recorded detent and power samples live in Sounds/, held in RAM and rate-varied ±2000 Hz per firing. A retune leaves the old station under rising static rather than cutting it, passes through noise, and reveals the new station band-limited and distorted before it opens out. World speakers now run the pocket radio's exact instrument and timings, after a week of them being two implementations that disagreed.

Config and schema

Three files, all generated rather than shipped, all hot-reloading.

  • Config/settings.xml and Config/radio.xml — 202 settings at schema revision 56, described by one table in CMMSettingsSchema.cs. Every entry carries since: (which schema added it) and, where a default has moved, changedIn:/was:. Both files are read as one chain, and a setting found in settings.xml still wins.
  • Config/contexts.xml — 71 contexts with their priority, source, fallback, warm-up, staleness and volume. A source may be a folder, a folder tree, or an .m3u playlist naming files anywhere on disk.
  • Config/context.lua — the policy, with a pristine copy embedded in the assembly as the fallback.

Migration rules: an added setting is appended under a banner naming the version that added it; a changed default is applied only if you were still on the old one, compared on the parsed value; a setting you delete stays deleted and follows the compiled default; files are written only at startup, never while you have them open.

Four games, one binary

One DLL loads on Alpha 20.7, Alpha 21.2, 2.6 and 3.2. The build fans out over an MSBuild GameVersion property that selects the game's Managed folder and stamps a per-version compile symbol; Debug deploys into that game's Mods folder, Release produces one zip in dist/.

The divergences the single binary must bridge are handled three ways:

  • Reflection bridges for field-versus-property and renamed-method splits, so neither token reaches a call site.
  • Name resolution for enums whose ordinals drift (GamePrefsCompat) and for types that only exist on one version (EmitterCompat.IsSeeThrough, BlockDoor.IsDoorOpen).
  • Runtime capability checks rather than version checks. This is the lesson of August 29: RuntimeSupported asking for a 3.0-only door type silenced every speaker on 2.6. Doors are now recorded as a capability, and a version missing one capability loses that feature rather than the subsystem it happened to be checked through.

Verification is tools/CmmApiDiff, which reads the shipped assembly's member references straight out of its metadata — without loading it, so it does not care that these are Unity assemblies for another runtime — and diffs them against what each game declares.

Principles it actually follows

Not stated as a manifesto anywhere. Inferred from what the code does — and in five cases now written down in the project's own review notes and memory.

1 · Make bugs impossible, don't fix them

The listener-anchored field's real argument is that nothing lives long enough to go stale. The embedded fallback context.lua means a bad edit can't kill audio. Excess-only attenuation means clear line of sight is 0 dB by construction. Building the craft recipes in code rather than XML means a block a version lacks is a recipe quietly not offered instead of a crash.

2 · Derive, do not latch

The newest of the six, and the one that cost the most. Nine separate reports in one week resolved to the same shape: an owner, plus event triggers to keep it fresh, where the answer should have been derived from the world each tick. Block ids cached per process against ids assigned per world. A carrier with an owner. A receiver with three. An advance decision overwritten by a tick that re-derived a stale answer over a fresh one.

3 · One model, never two that can disagree

The C# resolver was deleted at the Lua cutover rather than kept as a fallback. The acoustics audit's recorded verdict: "a fallback must be 'freeze the last published value', never 'compute the same quantity a different way'" — after three uncalibrated models switching live were measured 14 dB apart on the same wall. The August 29 rewrite of the world speaker retune is the same move: one instrument, one set of timings, the pocket radio's.

4 · No compensation constants

From the same review: "If it sounds wrong, find the wrong thing; never add a coefficient." Followed through in August, when four shape discounts were deleted at once because "all four were smuggling WHERE into HOW MUCH." And inverted into a warning: every world-emitter level knob set by ear while occlusion was leaking is a compensation for a bug that no longer exists, so those numbers are not preferences and are all wrong in the same direction.

5 · Nothing may vanish

Every term has a value or fades to one. This came from a real defect: the diffuse term switched off entirely at a threshold, producing 8–12 dB on/off from a floor(). The same rule produces "outside the field window reads clear, not sealed" and "hold to full, and never cut."

6 · The filesystem is the data model

Stations are folders. Music packs are folders. No manifest can disagree with the disk if there is no manifest. Both features shipped with less configuration than their own design documents planned for.

7 · A setting must mean the same thing everywhere

FavouriteWeight scaling with library size. Occlusion expressed in dB rather than virtual-distance units, so it doesn't change meaning when range changes. Door thresholds expressed as a fraction of open area rather than metres, so a closet and a drawbridge behave alike.

8 · Measure, don't estimate

The most recent addition, from the door-latency week: four wrong diagnoses in one session, all of them arithmetic over an untimed chain. The remedy is a stopwatch on every stage, and where a stage is still opaque, split it and time the halves.

The recurring failure modes

The project is unusually candid about these, and the same shapes keep coming back.

Mode 1

A changed default reaches nobody who already has the file

It bit three times in one day across three config files. WorldEmitterDoorMaxLoss was added with since: 1 against files already at schema 17, so it has never existed in any upgraded install — which is almost certainly why that knob "was never heard" despite being tried repeatedly. DetourDb 3 was agreed by ear and then never left the author's own config file. Radio tuning was judged for weeks against hand-edited values no migration could reach.

Mode 2

A guard nobody reads is worse than no guard

The config test printed the DoorMaxLoss bug hours before it was found by hand, and it was waved off as stale-baseline noise — because 34 other failures were also noise. The schema guard was later found to be checking a schema from three weeks earlier, and to crash on the first multi-valued was: that mattered. The project's own conclusion: "Fix the baseline or the net is decorative."

Mode 3

Silent fallbacks hide shipping bugs

The release zip went out without the dial sounds for want of one CopyToOutputDirectory — and failed silently by design, because a missing sound falls back to the synthesised click. Debug installs force-copy them, so every machine anyone tested on was fine and only the zip was wrong. The same week: two dark harnesses, and a guard that always failed.

Mode 4

The instrument measured itself

Every emitters-on soak run reported "STILL CLIMBING — leak suspect"; every emitters-off run of the same code said "PLATEAUED." The harness was holding three List<double> taking one entry per acoustics run — 79,498 runs over 12 hours — while the gauge measured managed-heap growth from a post-warmup baseline. It was reporting its own telemetry as the leak. The verdict then read one difference over four samples of an RSS number that bounces tens of megabytes on Windows' own schedule; it now takes 16 checkpoints and a least-squares slope.

Why these four are one bug

All of them are cases where the system's default behaviour on failure is to look fine. A missing setting runs on a compiled default. A noisy test suite reads as "known noise." A missing asset falls back to a synthesised one. A harness's own allocation is indistinguishable from the thing it is watching.

Each is individually a reasonable robustness decision, and collectively they form a system that cannot tell you when it is wrong. The 25 undecodable tracks found on August 30 are the purest instance: three separate diagnostics all agreed with the silence, because each was answering a slightly different question and every answer was correct.

The generalisation the project has recorded — "open the artifact", meaning list the actual shipped archive rather than trusting the build — is right, and understates the case. The broader version is: every fallback needs a way to say it fired.

Where it's going

Drawn from TODO.md, the release-candidate handoffs, the shape of the code, and — for the last part — inference.

Immediately: 1.0.5 final

The candidate line has run RC1 → RC5 in eight days and the remaining blockers are almost all listening, not building. A recurring phrase in the TODO is "built, deployed, in-game test pending" — a large amount of shipped work has been verified offline and not yet heard by a human in a running game. The named risks:

  • A levels pass. Every world-emitter level knob was set by ear while occlusion was leaking. Measured at one speaker: 2.3 dB before the fix, 9.0 dB after, same spot. Two have already been corrected; the rest need ears.
  • The context-music loudness hold, flagged as the highest-risk shipped change, for an exact reason: "A fault here is silence, the worst failure this mod has."
  • Door timing on 2.6, which is structural rather than tuning — every input the 3.x swing model needs is absent, and the honest answer is a binary at-rest aperture with the swing machinery disabled outright.

1.0.6, as currently scoped

  • Occlusion output shaping ported into the field — described in the TODO as "THE LAST THING the audio engine needs." Two curves: a soft knee so detour and gaps can never fully silence a speaker (stand behind a crate, still hear it), and a hard gate on the solid term only, so enough material produces true silence (a sealed vault). Detour can never silence; material can.
  • Stereo pairs. Lone speakers are already mono. What's unbuilt is two speakers of the same station close together each taking one channel, L/R assigned by lexicographic world position so it's stable across ticks, sessions and multiplayer clients. The render-flag bits were reserved for it back in July; the newest note reframes it correctly — channel is a lane property, not a point flag; a stereo pair is one tuner with two outputs.
  • Emitter squelch — a distance- or signal-dependent breakup so a distant world radio degrades like a radio rather than merely getting quieter.
  • A continuous FM dial — sweeping into a station rather than stepping, with partial signal and partial noise following how close you are. Scoped as 1.0.5a.
  • The fade-versus-hysteresis question — 39% of transitions interrupt a crossfade, and the structural choice between raising the 1.5 s eviction hysteresis and refusing a transition mid-fade has not been made.
  • Native heap accounting, so the soak becomes a real gate instead of an inconclusive one. Managed heap is provably flat; the native allocators are the only unverified surface and there is currently no instrument that can see them.
  • A DJ system, Fallout-style, listed as an idea.

What the system is quietly built for

Speculation — the trajectory

The stated 1.0.6 list is polish. The interesting signal is one line in a design note: "it must handle MOVING sources, because zombies get sound later."

That requirement is why the per-speaker acoustic model was abandoned after reaching 0.02 dB parity in native C. Nothing in the shipped feature set needs it — speaker blocks don't walk. It was a constraint imposed on the architecture for something that has not been built.

Everything around it points the same way. The field is source-agnostic and costs 0.11 µs per lookup, so the fiftieth source is free. The spatializer and reverb are source-agnostic. The mixer's voice array has headroom to twenty. The TODO's standing item is "convert anything to C that can be converted." The acoustic model does not care whether the thing making noise is a jukebox or a zombie behind a door.

The conclusion is hard to avoid: CMM is becoming a general game-audio engine that currently happens to play music. The diegetic authenticity pass on the roadmap — "emitters are functional but far from satisfactory as in-world objects" — is not a music goal. It is a world-simulation goal.

Speculation — the second trajectory, which is newer

The last fortnight added something the first ten weeks did not have: features aimed at the player's agency rather than the author's fidelity. The coverage panel exists so a stranger can diagnose their own silence. The tuner exists so a player can overrule a deterministic assignment. The craftable blocks exist so a player can put a speaker where no level designer did. Music packs exist so a third party can publish content for it.

Those four are a different kind of work from acoustic calibration, and they arrived together, at the release-candidate boundary. If the first ten weeks were about making the thing correct, the last two are the first evidence of making it somebody else's. The natural continuation is a content ecosystem: soundtrack packs as ordinary mods (already shipped), a DJ layer, stations that other mods can register, and eventually an emitter API that a different mod could drive.

Both trajectories share a dependency, and it is the unglamorous item on the list: the project must be able to trust its own instruments. Every one of the four recurring failure modes is a feedback problem, not a capability problem. As the surface grows from "music" to "all audio" and from "my install" to "other people's", the number of knobs that can be silently wrong grows with it. Regenerating the schema baseline so the config test stops crying wolf, and exporting native heap counters so the soak can certify, are worth more than any feature on the roadmap — because everything else is downstream of being able to tell when you are wrong.

The open question

If the trajectory holds, the interesting question for the project isn't which features land in 1.0.6. It's whether a mod can replace a game's entire audio presentation from the outside, across four game versions spanning years of API drift, without the game's cooperation.

The last ninety days say the hard parts — threading, decoding, spatialisation, occlusion, calibration, cross-version binding — are already solved.

A note on version numbers

The public upload numbers and the mod's own version don't line up. Uploads 1–8 track version bumps roughly 1:1; uploads 9–14 are all one line, informally "1.0.4b", because 1.0.5 has now spent nearly two months in development. ModInfo.xml has read 1.0.5 since July 3, which means a July development build and an August release candidate report the same version string. Worth knowing before quoting a version number, or before trusting one in a bug report.
